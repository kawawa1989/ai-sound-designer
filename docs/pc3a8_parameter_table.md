# PC3A8 のパラメータ表

`data/pc3a8_parameters/kva.json` は、PC3A8 のレシピで使うパラメータの一覧です。範囲・単位・役割・出典を書いています。
読み込みと検証は `src/synth_ai/adapters/pc3a8/parameters.py` で行います。

- 出典は Kurzweil PC3A Musician's Guide（V3）の本文ページ（例: `Musician's Guide 本文 6-43`）です
- マニュアルにない値は、実機の画面で読み、`source_ref` に「実機の画面で確認（日付）」と書きます
- 公式資料にも実機にもない値は書きません。分からないものは `verified: false` にし、`notes` に「要確認」と書きます

## KRONOS の表との違い

| 項目 | KRONOS（`al1.json`） | PC3A8（`kva.json`） |
| --- | --- | --- |
| 値 | 0〜99 などの目盛り（整数） | 秒・%・dB・Hz・セントの物理単位（小数） |
| 音源・フィルター | エンジンの固定の項目（OSC1 Waveform など） | アルゴリズムのブロックに置く機能（SAW、LOPASS など） |
| 前提 | エンジン（AL-1） | 基準音の配置（`layout`: Program 1025、Keymap 999 Silence、Algorithm 1、SAW → LOPASS → NONE） |
| 範囲が分からない項目 | 書かない | `verified: false` で、`min` / `max` を空にできる |

役割（`roles`）と選択肢のタグは、KRONOS の表と同じ名前を使います（例: `amp_eg_release`、`saw`）。
役割と選択肢のタグは機種共通の語彙で、`src/synth_ai/core/planning/roles.py` が正です（#20）。

## 項目

| フィールド | 内容 |
| --- | --- |
| `id` | 表の中で一意な ID（例: `kva.ampenv.decay.time`） |
| `page` / `section` / `name` | Program Editor のページ名（ソフトボタン名）、ページ内の位置、本体の表示どおりの名前 |
| `kind` | `float` / `int` / `choice` |
| `min` / `max` / `step` / `unit` | 範囲・刻み・単位。`verified: true` の数値の項目は `min` と `max` が必須 |
| `default` | Program 999 Default Program での値 |
| `base_value` | 基準音 1025 での値 |
| `steps_per_octave` | 周波数の値の 1 段が何分の 1 オクターブか（半音刻みなら 12） |
| `choices` | 選択肢（本体の表示どおり）とタグ |
| `roles` | レシピでの役割 |
| `source_ref` / `verified` / `notes` | 出典、確かめたかどうか、補足 |

`verified: false` の項目と、範囲が分からない項目は、レシピに使いません（`ParameterDef.usable`）。

## 刻みが一定でない値

AMPENV の時間は、値によって刻みが変わります。`values`（個別の値）と `step_ranges`（一定の刻みの区間）で、
本体で選べる値を書きます。`ParameterDef.clamp` は、その中でいちばん近い値に丸めます。
書いた区間より外の値は丸めません。

```json
"values": [0, 0.002, 0.005, 0.01],
"step_ranges": [
  {"start": 0.02, "end": 2.0, "step": 0.02},
  {"start": 2.0, "end": 5.0, "step": 0.04},
  {"start": 5.0, "end": 10.0, "step": 0.1},
  {"start": 10.0, "end": 15.0, "step": 0.5}
]
```

実機で確かめた範囲だけを書きます。上の例は AMPENV の Att1 Time で 15.0 秒まで確かめたものです。

## 実機で確かめた値（2026-11-14）

手順は `docs/manuals/pc3a8/read_parameter_values.md`。

| ID | 確かめた値 |
| --- | --- |
| `kva.alg.block1` | ブロック 1 の一覧にある発振器は SAW、SQUARE、SINE、SINE+、RES NOISE、SHAPED SAW、PWM。TRI はない |
| `kva.dspctl.lp_frq` | 16 Hz（C 0）〜25088 Hz（G 10）、1 クリックで半音 |
| `kva.dspctl.saw_pch` | −120〜60 ST |
| `kva.dspmod.lp_frq.src1` | 一覧に ENV2 がある |
| `kva.dspmod.lp_frq.depth` | −10800〜10800 ct |
| `kva.env2.att1.level` / `kva.env2.decay.level` | −100〜100% |
| `kva.ampenv.att1.time` | 刻み: 0, 0.002, 0.005, 0.01, 0.02 → 2.00 まで 0.02 → 5.00 まで 0.04 → 10.0 まで 0.10 → 0.5（15.0 まで確認） |

## 要確認の項目

- AMPENV の Decay・Release 1 と ENV2 の時間の刻み。Att1 と同じと思われるが、確かめていない（Release 1 は 0.05 付近が 0.02 刻みであることだけ確認。表では Att1 と同じ刻みを使う）
- 時間の 15 秒より上の刻み
- ブロック 1 の一覧にあるフィルター（2POLE LOWPASS など）の機能パラメータ。2 ブロックのフィルターを使えばレゾナンスを設定できる可能性があるが、基準音の配置（ブロック 2 は 1 スロット）では使っていない

## レシピでの使い方（#20）

`src/synth_ai/adapters/pc3a8/adapter.py` の `Pc3a8Adapter` が、この表を使ってレシピを作ります。
調整する項目の決め方は KRONOS と共通（`src/synth_ai/core/planning/`）で、表の `roles` でパラメータを引きます。

```bash
uv run synth-ai recipe runs/<analyze の出力> --synth pc3a8
```

- 基準音 1025 を呼び出し、そこから変える項目だけを、ページの順（KEYMAP → ALG → DSPCTL → DSPMOD → ENV2 → AMPENV）に並べる
- `usable` でない項目（`verified: false` など）は手順にしない
- 値はキャリブレーション曲線（`data/pc3a8_calibration/`、#22）から決める。曲線がないとき:
  - 時間の項目（秒）は、解析の時間の目標（ms）を換算して初期値にする。解析の測り方（例: アタックは 10%→90%）と本体の値の意味は同じではないので、録音して確かめる
  - それ以外（カットオフ、ENV2 の Depth、AMPENV の Dec1 Level）は値を空にして、音響目標だけを示す
- 一覧にない波形（三角波など）は選ばず、基準音の SAW のままにする
- ノイズとレゾナンスは、基準音の配置（SAW → LOPASS → NONE）では設定できないため、未確定事項として示す

### サンプルの再生が向く音（#21）

PC3A8 はユーザーサンプルを読み込めない（"The PC3A does not load samples"、本文 E-1）。
SoundSpec でサンプルの再生が最も有力な仮説になった音でも、取り込みは提案しない。

- レシピの `sample_alternative` に、できないことと代わりの方法を書く: KVA の発振器で近似する、ノイズ成分を別の Layer の RES NOISE で重ねる、ROM の Keymap を使う（Keymap の名前は、実機で確かめるまで挙げない）
- 非整数倍音やノイズのように、基準音の配置では再現しきれない点は `limitations`（再現の限界）に書く
- 取り込めない機種のレシピに `sample_alternative` がなければ、Core の `validate_recipe` がエラーにする（Capability の `user_sample_import` だけを見る）

## キャリブレーションの結果（#22、2026-11-14）

基準音 1025 KVA BASIC SAW、C4・ベロシティ 100 で、1 項目だけを変えて測った。手順は `docs/manuals/pc3a8/calibrate.md`、
曲線は `data/pc3a8_calibration/`。

| 項目 | 測った特徴 | 結果 |
| --- | --- | --- |
| AMPENV Att1 Time | アタック（10%→90%） | 0 s で 8.5 ms、0.1 s 以上ではおよそ設定の 0.78 倍（0.8 s → 635 ms） |
| AMPENV Dec1 Time | ディケイ | およそ設定の 0.9 倍（0.1 s → 95 ms、1.6 s → 1442 ms） |
| AMPENV Dec1 Level | サステイン（ピーク基準の dB） | 10% → −39.9 dB、45% → −19.9 dB、75% → −8.1 dB、90% → −3.1 dB。100% はディケイがなく、サステインとして測れない |
| AMPENV Rel1 Time | リリース（20 dB 下がるまで） | およそ設定の 0.2 倍（0.06 s → 21 ms、1.6 s → 314 ms）。0.02 s は短すぎて測れない |
| DSPCTL LP Frq | 持続部の明るさ（×f0） | 131 Hz → 2.4、1047 Hz → 4.3、4186 Hz → 7.6、25088 Hz → 13.2。対数で補間する（`parameter_scale: log`） |

- 曲線から逆引きすると、基準音の録音から基準音の設定（Att1 0 s、Dec1 0.10 s・75%、Rel1 0.06 s、LP Frq 25088 Hz）に戻る（`tests/adapters/pc3a8/test_adapter.py`）
- Dec1 Level の % は振幅の比ではない（75% は振幅の比なら −2.5 dB のはずが −8.1 dB）
- Rel1 の Time は 0% まで下がる時間で、解析のリリース（20 dB 下がるまで）よりかなり長い
- 曲線は C4 で測った。明るさは音程で変わるので、LP Frq は参照音との音程差だけずらす（1 オクターブ上なら Hz を 2 倍）

## CC での測定（#34、2026-11-14）

キャリブレーション用 Program 1026 KVA CC CAL（LP Frq を G 1 = 49 Hz、DSPMOD の LP Frq の Src1 を CC 14、Depth を +10800 ct）で、
CC 14 を送って LP Frq を動かし、自動で測った。手順は `docs/manuals/pc3a8/calibrate_cc.md`、曲線は
`data/pc3a8_calibration/cc/kva.dspctl.lp_frq__brightness_end.json`。カットオフは「49 Hz × 2^(10800 ct × CC/127)」と仮定した（下の表の値。#37 で換算を CC/128 に変えた）。

| CC | 仮定したカットオフ | CC で測った明るさ（×f0） | 手動の曲線での明るさ | 差 | 同じ明るさになるカットオフの差 |
| --- | --- | --- | --- | --- | --- |
| 20 | 131 Hz | 2.429 | 2.430 | −0.0% | −0.02 半音 |
| 34 | 260 Hz | 2.686 | 2.694 | −0.3% | +0.34 半音 |
| 48 | 518 Hz | 3.266 | 3.295 | −0.9% | +0.58 半音 |
| 62 | 1030 Hz | 4.255 | 4.293 | −0.9% | +0.45 半音 |
| 76 | 2049 Hz | 5.648 | 5.715 | −1.2% | +0.56 半音 |
| 91 | 4280 Hz | 7.557 | 7.657 | −1.3% | +0.60 半音 |
| 105 | 8514 Hz | 9.619 | 9.746 | −1.3% | +0.71 半音 |
| 119 | 16936 Hz | 11.806 | 11.953 | −1.2% | +0.79 半音 |
| 127 | 25088 Hz | 13.222 | 13.221 | +0.0% | 0.00 半音 |

- **CC で測った曲線は、手動の曲線と 1.3% 以内で合った**。途中の CC でもほぼ比例して動いている
- ただし CC の途中では、実際のカットオフが仮定より 0.3〜0.8 半音低い。CC が大きいほど差が開く。CC を 128 で割る換算だと、この差はほぼ説明できる（例: CC 105 で 0.70 半音、CC 119 で 0.79 半音）。CC 127 では最大の 25088 Hz と区別できない。マニュアルには「最大で Depth の分」とだけあり、換算は要確認
- **換算は CC/128 にした（#37）**。同じ測定を CC/128 で読み直すと、CC 20〜119 の差は ±0.26 半音以内（CC 62 以上は ±0.06 半音以内）になる。CC/127 では +0.34〜+0.79 半音ずれる。CC 127 は、CC/128 だと −0.84 半音になるが、25088 Hz 付近は明るさが変わらないので区別できない。`kva.json` の `cc_calibration` に `"divisor": 128` を書き、曲線のカットオフも CC/128 で書き直した

| CC | CC/127 の差 | CC/128 の差 |
| --- | --- | --- |
| 20 | −0.02 半音 | −0.15 半音 |
| 34 | +0.34 半音 | +0.11 半音 |
| 48 | +0.58 半音 | +0.26 半音 |
| 62 | +0.45 半音 | +0.04 半音 |
| 76 | +0.56 半音 | +0.06 半音 |
| 91 | +0.60 半音 | −0.01 半音 |
| 105 | +0.71 半音 | +0.01 半音 |
| 119 | +0.79 半音 | 0.00 半音 |
| 127 | 0.00 半音 | −0.84 半音（区別できない） |

- 差は 1 半音（LP Frq の 1 クリック）より小さいので、CC の曲線はレシピの逆引きに使える精度。いまは手動の曲線を使い、CC の曲線は `cc/` に置いたまま比較用にする

### ENVCTL で Rel1 を測る（#37、2026-11-14）

キャリブレーション用 Program 1027 KVA ENVCTL CAL（AMPENV の Rel1 Time を 1.60 s、ENVCTL の Release の Source を CC 15、Depth を 50.000x）で、
CC 15 を送って Rel1 を速くし、リリースを自動で測った。手順は `docs/manuals/pc3a8/calibrate_cc.md`、曲線は
`data/pc3a8_calibration/cc/kva.ampenv.rel1.time__release_time.json`。Rel1 は「1.6 s ÷ 50^(CC/128)」と仮定した。

| CC | 仮定した Rel1 | CC で測ったリリース | 手動の曲線でのリリース | 差 | 同じリリースになる Rel1（手動の曲線から） | 比例（1 + 49 × CC/128 倍）なら |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 1.600 s | 313.1 ms | 313.5 ms | −0.2% | 1.598 s | 1.600 s |
| 23 | 0.792 s | 157.3 ms | 157.4 ms | −0.1% | 0.791 s | 0.163 s |
| 45 | 0.404 s | 83.6 ms | 83.0 ms | +0.7% | 0.408 s | 0.088 s |
| 68 | 0.200 s | 43.1 ms | 42.5 ms | +1.3% | 0.203 s | 0.059 s |
| 91 | 0.099 s | 24.8 ms | 25.9 ms | −4.3% | 0.091 s | 0.045 s |
| 107 | 0.061 s | 18.1 ms | 20.8 ms | −12.9% | 0.060 s 以下（曲線の下端） | 0.038 s |
| 127 | 0.033 s | 測れない | — | — | — | — |

- **ENVCTL の倍率は、CC に対して指数的に効く**（CC/128 で Depth の何乗か）。CC 0〜68 で手動の曲線と 1.3% 以内。比例の仮定とは 5 倍近く違うので外れ
- CC/127 と CC/128 の差は 1% 前後で、この測定では区別しにくい。読み直すと CC/128 がわずかに近い（例: CC 45 で 0.408 s に対し /128 は 0.404 s、/127 は 0.400 s）。LP Frq と同じ CC/128 にそろえた
- 0.1 s より短いところ（CC 91 以上）は、リリースの解析が 20 ms 前後で下げ止まるため合わない。手動の曲線でも 0.06 s で 21 ms、0.02 s は測れていない。CC の換算の問題ではなく、測り方の下限として扱う
- いまは手動の曲線を使い、CC の曲線は `cc/` に置いたまま比較用にする
- **あとで分かったこと（#40）**: この測定の間、CC 15 が本体全体の音程も動かしていた（CC 0 で 233 Hz、127 で 293 Hz。C4 は 262 Hz）。リリースの時間は音程の影響が小さく、手動の曲線と合ったので結果は残すが、CC 15 はこれ以降送らない（`docs/safety.md`）


### DSPMOD の Depth を CC で測る（#40、2026-11-14）

キャリブレーション用 Program 1028 KVA ENV2 CAL（LP Frq を G 1 = 49 Hz、DSPMOD の LP Frq の Src2 を ENV2・DptCtl を CC 14・MinDepth 0 ct・MaxDepth 10800 ct、
ENV2 を Att1 0 s・100% / Dec1 100%）で、CC 14 を送って Depth を動かし、持続部の明るさを測った。ENV2 は 100% のまま下がらない。
曲線は `data/pc3a8_calibration/cc/kva.dspmod.lp_frq.depth__brightness_end.json`。Depth は「10800 ct × CC/128」と仮定した。

| CC | 仮定した Depth | 49 Hz から上げたカットオフ | CC で測った明るさ | 手動の LP Frq の曲線での明るさ | 差 |
| --- | --- | --- | --- | --- | --- |
| 28 | 2363 ct | 192 Hz | 2.524 | 2.576 | −2.0% |
| 43 | 3628 ct | 398 Hz | 3.010 | 3.065 | −1.8% |
| 57 | 4809 ct | 788 Hz | 3.856 | 3.903 | −1.2% |
| 71 | 5991 ct | 1560 Hz | 5.100 | 5.147 | −0.9% |
| 85 | 7172 ct | 3085 Hz | 6.741 | 6.784 | −0.6% |
| 100 | 8438 ct | 6409 Hz | 8.855 | 8.882 | −0.3% |
| 114 | 9619 ct | 12681 Hz | 11.052 | 11.024 | +0.3% |
| 127 | 10716 ct | 23895 Hz | 13.219 | 13.064 | +1.2% |

- **ENV2 が 100% のとき、カットオフは Depth の分だけ上がる**（手動の LP Frq の曲線と 2% 以内）。レシピの Depth の初期値（LP Frq の曲線から、発音直後と終盤のカットオフの差をセントにする）は、この前提で正しい
- Src2 の MinDepth〜MaxDepth は、DptCtl の CC に正比例して動く（CC/128）
- CC 0・14（49・97 Hz）は手動の曲線の下端（131 Hz）より低いので比べていない
- **Src2 の MinDepth と MaxDepth を同じ値にすると、ENV2 はカットオフを動かさなかった**（明るさが一定）。理由は要確認。ENV2 Dec1 Time の測定には Src1 を使った
- 最初の測定（18:33）は、CC 15 の影響で音程が 2 半音低く、明るさ（×f0）が最大 10% 高く出たので捨てた（`docs/safety.md` の「CC を送る条件」）

### ENV2 Dec1 Time を測る（#40、2026-11-14）

1028 を保存せずに、DSPMOD の LP Frq を Src1 ENV2・Depth 7200 ct・Src2 OFF、ENV2 の Dec1 Level を 0% にして、Dec1 Time を手で変えて測った。
曲線は `data/pc3a8_calibration/reference/kva.env2.decay.time__brightness_decay_time.json`（レシピには直接使わず、下の計算の確認に使う）。

| Dec1 Time | 暗くなるまでの時間 |
| --- | --- |
| 0.1 s | 106 ms |
| 0.2 s | 136 ms |
| 0.4 s | 196 ms |
| 0.8 s | 326 ms |
| 1.6 s | 576 ms |
| 3.2 s | 1056 ms |

- 暗くなるまでの時間（明るさが発音直後と終盤の中間に下がるまで）は、Dec1 Time のおよそ 0.3 倍 + 75 ms。0.1〜1.6 s は 2 回測って同じ値だった
- これまでのレシピは目標の時間をそのまま秒にしていた（740 ms → 0.74 s）。#23 の試行 003 では 0.74 s で 417 ms と速すぎた。曲線を使うと 2.15 s になる
- 3.2 s は押さえる時間 3 秒で測ったので、ENV2 が下がりきる前に終盤の明るさを取っている。少し短めに出ている可能性がある
- 曲線は LP Frq 49 Hz・Depth 7200 ct で測った。**LP Frq と Depth が違うと、暗くなるまでの時間も変わる**。この曲線をそのままレシピに使った試行 005（Dec1 Time 2.15 s）は、ENV2 が下がりきらず持続部が明るすぎた（`docs/pc3a8_trial_report.md`）
- そこでレシピは、**LP Frq の曲線から計算する**。ENV2 は一定の速さで下がり、カットオフは対数で一定の速さで下がるので、明るさが中間になるカットオフが対数で何割下がったところかを LP Frq の曲線で求め、Dec1 Time =（目標 − 80 ms）÷ その割合 とする。80 ms は解析の遅れで、上の 6 点と計算の差の平均（74〜89 ms）
- 計算は上の 6 点と合う（0.2 s 以上で 10% 以内）。#23 の参照音では 1.33 s になり、1.34 s で録った試行 006 は暗くなるまでの時間 707 ms（参照 747 ms）だった
