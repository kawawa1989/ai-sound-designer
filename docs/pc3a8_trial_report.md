## レシピ（最初に出したもの）

| ページ | 項目 | 値 |
| --- | --- | --- |
| ALG | ブロック 1 / 2 | SAW / LOPASS |
| DSPCTL | LP Frq | 87 Hz（F 2） |
| DSPMOD | LP Frq › Src1 / Depth | ENV2 / 8606 ct |
| ENV2 | Att1 Level・Time / Dec1 Time・Level | 100%・0 s / 0.74 s・0% |
| AMPENV | Att1 Level・Time / Dec1 Time・Level / Rel1 Time | 100%・0 s / 0.19 s・86% / 1.34 s |

- LP Frq は C4 で測った曲線を、参照音の C3 に合わせて 1 オクターブ下げた値
- Depth は LP Frq の曲線から、発音直後と終盤の明るさに当たるカットオフの差を出した初期値（ENV2 の曲線は測っていない）
- ENV2 Dec1 Time は、暗くなるまでの時間（740 ms）をそのまま秒にした初期値

## 分かったこと

- **レシピの値が正しく入れば、明るさの時間変化は再現できた**（003）。持続部の明るさは参照とほぼ同じ（2.57 / 2.5）
- **001・002 はレシピの一部が本体に入っていなかった**。002 では ENV2 Dec1 Level が 100% のままで、ENV2 が下がらず、カットオフが開いたままだった
  - 手順書（`run_trial.md`）に、設定後に読み返す項目の一覧を入れた
  - このときの比較の提案（「LP Frq を下げる」「Depth を上げる」）は原因を指していなかった。Depth を上げると、かえって明るくなる
- **フィルターとアンプの効き方が重なる**。カットオフが下がると音量も下がるため、解析ではアンプのディケイが長く（753 ms）、サステインが小さく（−11.3 dB）見えた
  - 004 で AMPENV のディケイをやめる（Dec1 Level 100%）と、サステインは −6.8 dB に近づいた。ディケイの長さは変わらない（フィルターによる音量の下がり方のため）
- **倍音の傾きの差（参照 −6.0 → 録音 −11.8 dB/oct）は、この配置では埋めにくい**。1 ブロックの LOPASS は傾きが緩やかで、参照の急なフィルターとは形が違う。再現の限界として扱う
- 音程（+0.3 セント）、アタック、リリースは参照に合った

## ENV2 Dec1 Time を直した試行（#40、2026-11-14）

- 005・006 は 1025 からレシピどおりに設定し直して録った（AMPENV Dec1 Level は 86%）。試行 003 と違うのは ENV2 Dec1 Time だけ
- 暗くなるまでの時間（参照 747 ms）は、003（0.74 s）で 417 ms、005（2.15 s）で 867 ms、**006（1.34 s）で 707 ms**
- 005 は、比べる 1.8 秒の間に ENV2 が下がりきらず、持続部が明るすぎた（4.22 / 2.5）。1028（LP Frq 49 Hz・Depth 7200 ct）で測った曲線は、条件の違うレシピにそのまま使えなかった
- 006 は LP Frq の曲線から計算した値で、明るさの時間変化と持続部の明るさが参照に合った。距離は 7.6 dB で 003（7.3 dB）とほぼ同じ
- 006 のリリースは、最初の解析で 843 ms と出た。押さえている間にフィルターが閉じて音量が下がるため、平らな区間が 2 つ（下がる前と後）でき、解析がいちばん長い区間（下がる前）の終わりをリリースの始まりと見ていた
  - #42 で、リリースを離す直前の平らな区間から測るようにした（解析器 0.2.3）。006 は 262 ms になり、003・004 と同じになった。001〜005 と参照音の値は変わらない

## 解析と提案を直したあとの試行（#42・#44、2026-11-14）

- 007 は、#42（リリースの解析）と #44（比較の提案）を入れたあと、レシピを作り直して 1025 から設定し直して録った。レシピは 006 と同じ（ENV2 Dec1 Time だけ 1.32 s）
- リリースは 262 ms で参照（264 ms）と合った。持続部の明るさ・暗くなるまでの時間・サステインは 006 と同じ
- 有意な差は、発音直後の明るさ（参照 13.7 → 18.3 ×f0）と明るさの変化（0.18 → 0.14）だけ。調整案は「Depth を下げる」の 1 件で、AMPENV の値を出す提案は出なかった
- 本体の音量か入力ゲインを 006 から変えたため、007 の録音のピークは −17.9 dBFS（006 は −3.9 dBFS）だった
  - 008 は本体の音量を最大にしてクリップした（+1.2 dBFS）。発音開始のずれが +310 ms と出るなど、比較が崩れた
  - 009 は入力ゲインを下げて −8.8 dBFS で録った。特徴の値は 007 と同じ（違いは 0.01 以内）。比較は音量をそろえるので、クリップしなければ録音の大きさでは結果は変わらない
  - 試行どうしを比べるときは、音量とゲインを変えない（`run_trial.md` の注意）

- 010 は、残った差（発音直後が明るい）に合わせて Depth を 8606 → 7200 ct に下げた。LP Frq の曲線（C4 で測定）は上の端で明るさ 13.2 までしかなく、参照の 13.7（C3）は範囲の外なので、計算ではなく試しの値にした
  - 発音直後の明るさは 18.3 → **13.5**（参照 13.7）、明るさの変化は 0.14 → **0.19**（参照 0.18）になり、どちらも有意な差でなくなった。距離は 7.6 → **6.3 dB** で、これまでで最も小さい
  - 持続部の明るさ（2.57）は変わらず、暗くなるまでの時間は 707 → 667 ms（参照 747 ms、有意な差ではない）
  - 有意な差はディケイ（174 ms、参照 134 ms、差の大きさ 1.01）だけ。調整案は AMPENV Dec1 Time を短くするもので、#44 のとおり値は出さず、フィルターの影響の注意が付いた
  - レシピの Depth（8606 ct）が明るすぎたのは、Depth を LP Frq の曲線から出しているため。曲線の上の端より上は外挿になる。曲線を参照と同じ C3 でも測れば、上の端の明るさが高くなり、外挿しなくて済む見込み（要確認）
